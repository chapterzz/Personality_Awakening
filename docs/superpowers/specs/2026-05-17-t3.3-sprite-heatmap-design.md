## 1. 背景与目标

### 任务书（T3.3）

开发 **类型 × 精灵** 矩阵热力图：CSS Grid + 动态颜色映射；横轴 16 种 MBTI 类型，纵轴精灵角色，颜色深浅表示人数。

### 验收标准

| 项       | 要求                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| 数据准确 | 单元格人数与 API `spriteHeatmap` 一致；E 型仅在曦光行有数，I 型仅在月影行有数 |
| 颜色直观 | 同行内深浅随人数变化；两行使用可区分色相；附简易图例                          |
| 响应式   | 375px 起可横向滚动；行标签列 sticky，不遮挡数据                               |

### 现状

- `apps/web/src/components/dashboard/sprite-heatmap.tsx` 已有初版 Grid，但：单色 `primary`+opacity、无图例、无登录高亮、无 Vitest、移动端仅 `overflow-x-auto`。
- 后端 `DashboardService` 已按 E/I 映射精灵，稀疏数组由前端 `?? 0` 补全。

## 2. 方案对比

| 方案                       | 说明                                     | 优点                                             | 缺点                            | 结论     |
| -------------------------- | ---------------------------------------- | ------------------------------------------------ | ------------------------------- | -------- |
| **A. CSS Grid + CSS 变量** | 延续现有结构，提取可测纯函数             | 符合 PRD/Tech SPEC；与 T3.2 主题变量一致；包体小 | 需手写 sticky/图例              | **采用** |
| B. Recharts 热力图         | 使用 `ResponsiveContainer` + 自定义 Cell | 与柱图库统一                                     | 原生热力图定制差、16 列标签拥挤 | 不采用   |
| C. Canvas 绘制             | 自绘矩阵                                 | 极致性能                                         | 超范围、无障碍与主题切换成本高  | 不采用   |

## 3. 组件设计

### 3.1 文件职责

| 文件                      | 职责                                                |
| ------------------------- | --------------------------------------------------- |
| `sprite-heatmap.tsx`      | 展示矩阵；导出纯函数供单测                          |
| `sprite-heatmap.spec.tsx` | Vitest：计数、透明度、配色、渲染                    |
| `dashboard/page.tsx`      | 传入 `data` 与 `highlightType={comparison?.myType}` |

### 3.2 数据与矩阵规则

- **横轴**：固定 16 型顺序（与后端 `ALL_MBTI_TYPES` 一致，便于对照柱图）。
- **纵轴**：`['曦光领航精灵', '月影探索精灵']`。
- **单元格 count**：`data.find(d => d.type === t && d.sprite === s)?.count ?? 0`。
- **maxCount**：`Math.max(1, ...data.map(d => d.count))`，避免除零。
- **语义**：每个 MBTI 类型只对应一只精灵（E→曦光，I→月影），另一行恒为 0；热力图展示「类型落在哪只精灵行」的分布密度。

### 3.3 颜色映射（导出函数）

```typescript
// 行基色
resolveSpriteRowColor(sprite): 'var(--chart-1)' | 'var(--chart-2)'

// 透明度：0 → 0.08；>0 → 0.25 + 0.75 * (count / maxCount)
getHeatmapCellOpacity(count, maxCount): number
```

- 单元格：`backgroundColor: resolveSpriteRowColor(sprite)` + `opacity`（不用整格 `opacity` 叠在文字上时改用 `color-mix` 或内联 `background` 混色 — **实现选用 `color-mix(in srgb, base  X%, transparent)`** 以保证数字可读性）。
- **图例**：区块底部「少 — 多」渐变条，使用曦光行基色示意。

### 3.4 登录用户高亮（与 T3.2 一致）

- 可选 prop：`highlightType?: string | null`。
- 该类型所在列：表头字重加粗 + `chart-3` 色；数据格 `ring-2 ring-[var(--chart-3)]`。
- 有 `highlightType` 时副标题：「高亮为你的类型：INFP」。

### 3.5 响应式

- 外层 `overflow-x-auto`，内层 `min-w-[520px]`。
- 首列（精灵名）`sticky left-0 z-10 bg-card`。
- 触控格最小 32×32px（`min-h-8 min-w-8`）。

### 3.6 无障碍

- 每个非零格 `title`：`{type} · {sprite}：{count} 人`。
- 表头 `scope` 等效：使用语义化 `role="grid"` 可选；至少保留 `title` 与可见数字。

## 4. 测试策略（TDD）

| 用例                     | 断言                                            |
| ------------------------ | ----------------------------------------------- |
| `getHeatmapCount`        | 稀疏数据正确取值；缺失为 0                      |
