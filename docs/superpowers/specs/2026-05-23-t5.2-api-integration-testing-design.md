# T5.2 API 集成测试（Golden Path）— 设计规格

**日期**: 2026-05-23  
**范围**: Phase 5 — 用 **Jest + supertest**（`apps/api/test/*.e2e-spec.ts`）覆盖任务书核心路径「注册 → 测评 → 看板」的 **HTTP 契约与数据流**，验收 **`pnpm test:integration` 100% 通过**。  
**方案**: **API 集成测方案**（替代原 Playwright 版 `2026-05-23-t5.2-e2e-testing-design.md`）  
**跳过**: **T5.1 安全审计**（本 spec 说明缺口与补偿策略）

**依赖**: T1.4–T4.8 后端模块已交付；现有 11 个集成 spec、约 58 条用例  
**并行**: 可与 T5.3 性能、T5.4 部署文档并行；**不阻塞** T5.1 补做  
**不修改**: 本阶段仅文档；批准前不改 `apps/`、`e2e/`、`prisma/` 业务代码

## 1. 背景与目标

### 1.1 任务书（T5.2 原文）

> 编写 Playwright/Cypress 脚本覆盖核心流程（注册 → 测试 → 看板）；自动化测试通过率 **100%**。

### 1.2 用户决策（2026-05-23）

**不采用 Playwright/Chrome 浏览器 E2E**，改为 **API 集成测试**（Jest + supertest，`apps/api/test/`），仍跳过 T5.1。

### 1.3 为何改为 API 集成测

| 维度                        | 原 Playwright 方案                         | API 集成测方案                                                                        |
| --------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------- |
| 验证焦点                    | 跨页 UI、Recharts 渲染、Header 导航        | HTTP 契约、DB 聚合、JWT 鉴权、计分输出                                                |
| 稳定性                      | webServer 双进程、选择器/超时 flaky        | Nest TestingModule + supertest，CI 已纳入 `test:gate`                                 |
| 与门禁关系                  | 需额外 `pnpm test:e2e`（不在 `test:gate`） | **`pnpm test:integration` 已在 `test:gate` 内**                                       |
| T5.2 字面「注册→测试→看板」 | UI 点击 + 演示 TestResult 勾选             | 等价 HTTP 链：`PUT /progress` → `POST /auth/register`（finalize）→ `GET /dashboard/*` |
| 「测试→报告」               | `/report` 页 DOM 断言                      | **`POST /scoring/mbti`** 返回 `scores` + `mbti_type`（报告页数据源）                  |
| 已有资产                    | 14 条 Playwright 保留作回归，**不删**      | 58+ 条集成测已覆盖模块级行为；本任务 **补 Golden Path 串联缺口**                      |

**结论**: T5.2 收口目标从「浏览器 E2E 100%」调整为「**集成测 Golden Path 100%** + 既有 Playwright 作可选 UI 回归」，与 `PPA_Tech_SPEC.md` §5 日常门禁（`test:gate` = integration）对齐。

### 1.4 验收标准（本任务 — API 版）

| ID   | 标准                                                                                                                                      |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| AC-1 | `pnpm test:integration` **全部通过**（含既有用例 + 本任务新增）                                                                           |
| AC-2 | 至少 **1 条** 集成 spec 串联 **注册演示 TestResult → GET /dashboard/stats + /dashboard/my-comparison**                                    |
| AC-3 | 至少 **1 条** 集成 spec 串联 **测评完成态 progress → POST /scoring/mbti → 报告所需字段**（可选延伸：register finalize → 看板聚合）        |
| AC-4 | **Guest vs 已登录** 看板 API：`/dashboard/stats` 公开；`/dashboard/my-comparison` 401/200 语义明确（可新增 smoke 或强化既有用例文档归属） |
| AC-5 | 新增用例复用 **`apps/api/test/helpers/`**（或等价共享模块），前缀清理 `e2e-golden-*`，避免与模块 spec 重复断言                            |
| AC-6 | **`test:gate` 不变**（不含 Playwright）；**不新增** `test:gate:release` 加 e2e                                                            |
| AC-7 | 文档：本 design + HTML 计划 + md 任务清单；按需更新 `docs/本地环境调试指南.md`（集成测 DB 前置一句即可）                                  |

## 3. 跳过 T5.1 的影响、缺口与补偿

| T5.1 原计划              | 对 T5.2 的影响             | 补偿策略                                                                                                   |
| ------------------------ | -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| XSS / CSRF 浏览器向量    | API 集成测 **不**替代 DAST | 框架默认 + 后续 T5.1；本任务 **不** 增 payload 用例                                                        |
| Admin/CMS 越权           | 任务书曾期望 T5.1 覆盖     | **已有** `admin-questionnaire/avg/library.e2e-spec.ts`（401/403）；T5.2 **不再** 增 Playwright Admin guard |

| 审计日志                 | 无表可验                   | **Out of scope**                                                                                           |
| Rate limiting / 批量导出 | 无专项 API                 | T5.1 补做时再增                                                                                            |

**结论**: 跳过 T5.1 **不阻塞** T5.2 API Golden Path；Admin 403 **已由集成测覆盖**，无需浏览器补偿。

## 6. 推荐架构

### 6.1 用例分层

```
Tier 0 — 既有模块 spec（~58 tests）     不删，跑通即回归
Tier 1 — Guest 看板 API smoke            golden-path-guest-dashboard.e2e-spec.ts（或合并 Tier 2）
Tier 2 — Golden Path 注册→看板           golden-path-register-dashboard.e2e-spec.ts
Tier 3 — 测评→计分→（可选）看板          golden-path-assessment-report.e2e-spec.ts
Tier 4 — Questionnaire 公开 API smoke    questionnaire-public.e2e-spec.ts（P1，G3 选用）
```

### 6.2 新增 Helper 模块

**`apps/api/test/helpers/golden-path-helpers.ts`**

- `uniqueNickname(prefix)` → `e2e-golden-${prefix}-${uuid}`
- `registerWithDemoTestResultViaHttp(app, { nickname, password, mbtiType })` → `{ token, userId }`（复刻 web 客户端三步）
- `seedGuestAdaptiveStandardComplete(app, sessionId)` — 从 Playwright helper 移植（supertest 版）
- `cleanupGoldenPath(prisma, prefix)` — 删 TestResult / TemporarySession / User

### 6.3 数据策略

| 场景                | 策略                                                                                                                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 注册演示 TestResult | `guest_session_id` + `finalize_submission` + `submission.mbti_type`（与 `auth-api.ts` 一致）                                                                                     |
| 看板 stats 计数     | 断言 **相对增量**（before/after `totalUsers`）或查 `typeDistribution` 含 INFP，避免依赖全库 seed                                                                                 |
| 测评→scoring        | 使用 `adaptive-demo-v1` sequence API 生成完成态 progress；signals 用 **固定 ENTJ 等价 payload**（与 `e2e/report-page-from-standard` mock 一致）或从题库 metadata 推导（G2 选型） |
| 清理                | `afterEach` 按 `e2e-golden-*` 前缀删除                                                                                                                                           |

### 6.4 门禁

| 命令                    | 用途                                              |
| ----------------------- | ------------------------------------------------- |
| `pnpm test:integration` | **T5.2 验收命令**                                 |
| `pnpm test:gate`        | 日常合并（static + unit + integration），**不变** |
| `pnpm test:e2e`         | Playwright **可选** UI 回归，**不是** T5.2 收口   |

## 7. 新增 Spec 与用例列表

### 7.1 `golden-path-register-dashboard.e2e-spec.ts`（P0）

| #   | 用例                               | HTTP 步骤                                                                                | 断言                                            |
| --- | ---------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 1   | 注册演示 TestResult 后看板个人对比 | `PUT /progress` → `POST /auth/register`（finalize INFP）→ `GET /dashboard/my-comparison` | `myType === 'INFP'`，`typeRank >= 1`            |
| 2   | 同上链路透传 stats                 | 上一步后 `GET /dashboard/stats`                                                          | `typeDistribution` 含 INFP 且 count 增量 ≥ 1    |
| 3   | 纯注册无 TestResult                | `POST /auth/register` → `GET /dashboard/my-comparison`                                   | `data === null`，`message === 'no_test_result'` |

### 7.2 `golden-path-assessment-report.e2e-spec.ts`（P0）

| #   | 用例                               | HTTP 步骤                                                                                              | 断言                                                                    |
| --- | ---------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| 1   | 标准完成态 → scoring               | `POST /questionnaire/adaptive-demo-v1/sequence`（可选）→ `PUT /progress` 完成态 → `POST /scoring/mbti` | `mbti_type === 'ENTJ'`（或 seed 约定类型），四维 `scores.*.winner` 存在 |
| 2   | AVG 收束态 → scoring               | `PUT /progress`（AVG closing，复用 progress spec body）→ `POST /scoring/mbti`（AVG signals）           | `mode === 'AVG'`，`mbti_type` 与 signals 一致                           |
| 3   | （G2-A）测评后注册 finalize → 看板 | 完成态 progress → register finalize（submission 用 scoring 结果）→ `GET /dashboard/stats`              | stats 含该 `mbti_type`                                                  |

### 7.3 `golden-path-guest-dashboard.e2e-spec.ts`（P1，可与 7.1 合并）

| #   | 用例                                  | 断言                                                           |
| --- | ------------------------------------- | -------------------------------------------------------------- |
| 1   | 无 JWT `GET /dashboard/stats`         | 200，`typeDistribution.length === 16`，不要求 `totalUsers > 0` |
| 2   | 无 JWT `GET /dashboard/my-comparison` | 401                                                            |

### 7.4 `questionnaire-public.e2e-spec.ts`（P1，G3 选用）

| #   | 用例                                            | 断言                             |
| --- | ----------------------------------------------- | -------------------------------- |
| 1   | `GET /questionnaire/adaptive-demo-v1`           | 200，含 `questions`              |
| 2   | `POST /questionnaire/adaptive-demo-v1/sequence` | 200，`ordered_question_ids` 非空 |
